# Проверка безопасности — 31 октября 2026

Использован установленный security-audit skill. Выполнены четыре независимые
задачи reconnaissance и две повторные проверки измененного кода. Полный
формальный workflow навыка **не завершен**: нет подтвержденного OS sandbox с
отключенной сетью, allowlist окружения, read-only исходниками и ограничениями
ресурсов. На Windows также отказали валидаторы навыка: `OS no-follow and
nonblocking input protection is unavailable`. Формальные hunting/critic/
verification-фазы не завершены; пять единиц coverage отложены. Это частичная
проверка исходников, а не сертификат отсутствия уязвимостей.

Полные артефакты попытки аудита находятся локально вне проекта:
вне опубликованного репозитория (путь к рабочей машине не публикуется).
Предыдущих ledger не было. Подтвержденных независимой эксплуатационной
проверкой уязвимостей нет; это не означает, что все возможные риски исключены.

## Исправления и проверенные свойства исходников

- Четыре типа данных Health Connect — только READ; добавлен отдельный
  READ_HEALTH_DATA_HISTORY, с проверкой доступности и запросом согласия.
  health обновлен до 12.2.0. ACTIVITY_RECOGNITION проверяется и запрашивается
  перед Health Connect; лишних WRITE нет.
- MainActivity — FlutterFragmentActivity. Экспорт launcher и статического
  rationale обоснован; Android 14 alias защищен START_VIEW_PERMISSION_USAGE.
  Обработки/пересылки входящих Intent extras/URI в своем коде нет.
- Запрещены backup, legacy full backup, cloud backup и device transfer всех
  областей данных; cleartext отключен. INTERNET включен для HTTPS-запросов Open Food Facts; CAMERA опциональна для сканера.
  Debug/profile оставляют INTERNET для инструментов Flutter.
- Inter Regular/Medium/SemiBold/Bold поставляется в assets/fonts с OFL.
  GoogleFonts.config.allowRuntimeFetching=false; тема использует локальное семейство.
- App-owned print/debugPrint/Log отсутствуют. Для release включен R8 и правило
  удаления перечисленных android.util.Log вызовов зависимостей. Это не
  утверждение об удалении всех возможных Dart/native stdout/logging путей.
- Границы чисел проверяются и в UI, и перед записью: продукт ≤1000 ккал/100 г,
  каждый макронутриент ≤100 г/100 г, порция ≤10 000 г, окружность ≤500 см,
  дневная цель ≤20 000 ккал/2000 г на каждый макронутриент/200 000 шагов.
  Это технические пределы ввода, не рекомендации по питанию или активности.
  Имя ≤120 UTF-16 единиц, заметка ≤2000; JSON целей ≤4096.
- Health Connect значения проверяются на конечность и диапазон перед UI.
- Release-подпись читает приватный key.properties; только отсутствие файла
  включает debug fallback. Неполная конфигурация, каталог вместо файла и
  отсутствующий keystore приводят к ошибке. Ключи исключены из Git.
- Экспорт/импорт JSON через Android Storage Access Framework не требует
  broad-storage permissions. Импорт ограничен 10 МБ и 50 000 записей каждого
  типа; проверяются формат/version, диапазоны, даты, имена и уникальность дней.
  До замены данных показывается подтверждение. Все четыре коллекции заменяются
  одной Isar-транзакцией; при ошибке восстанавливаются прежние цели в prefs.
  Isar и SharedPreferences не образуют общую crash-atomic транзакцию:
  отключение питания между commit двух хранилищ может потребовать повторного
  импорта. Экспорт содержит персональные данные открытым текстом; UI сообщает
  об этом. Health Connect данные в экспорт не включаются.
- Шаги берутся только агрегатом Health Connect. removeDuplicates и приоритет
  источников разрешают совпадающие записи; интервалы активных калорий с
  разными границами автоматически не склеиваются. Это не гарантия устранения
  всех возможных дубликатов, созданных внешними приложениями.

## Хранение и зависимости

Isar содержит дневник/замеры в app-private directory. SharedPreferences
содержит цели, оформление и расписание, не Health Connect записи и не ключи/токены. Собственного
шифрования БД нет: защита опирается на Android sandbox и шифрование устройства.
Защита от root/компрометации ОС не заявляется. Отключение backup не заменяет
проверку поведения целевых OEM-устройств.

OSV querybatch проверяет точные версии hosted Pub-зависимостей; результат
записывается в `.dart_tool/security-dependencies.json`. В CI проверка падает
при advisory-совпадении или недоступном сервисе. Maven/NDK advisories этим
сканером не покрываются. Старые версии, выбранные под Flutter 3.35.7/SDK 35,
сами по себе не считаются найденной уязвимостью. pubspec.lock сохраняется.

`node tool/security_check.mjs --advisories` — ограниченная regression-проверка
исходного manifest/config и Pub advisory-сканирование, не полный аудит.
Перед запуском: `dart pub deps --json > .dart_tool/dependency-tree.json`.
Основной manifest не равен merged manifest: конечные permissions, подпись,
логирование и runtime consent проверяются отдельно по готовому APK/эмулятору.

Все выполняемые в ходе разработки build/test/emulator-команды — отдельно
авторизованные проверки реализации, а не skill-compliant security reproduction.

## Дополнение quant 1.2.0

- READ-права Health Connect не расширены до WRITE. Включены INTERNET для OFF,
  CAMERA (runtime, необязательное оборудование), POST_NOTIFICATIONS,
  SCHEDULE_EXACT_ALARM и RECEIVE_BOOT_COMPLETED. USE_EXACT_ALARM не используется.
- Ресиверы плагина уведомлений не экспортированы. Расписание восстанавливается
  после boot/update; при возвращении в приложение учитывается часовой пояс.
  Запрос POST_NOTIFICATIONS только по явному действию. Без exact-доступа —
  неточный режим. На экране блокировки содержимое скрыто (private).
- Текст поиска и штрихкод отправляются только world.openfoodfacts.org по HTTPS.
  Редиректы запрещены, есть таймауты и предел ответа 2 МБ. Медицинские данные
  не включаются в запросы. Парсер отклоняет неконечные, неполные и чрезмерные КБЖУ.
- Каталог расширяется аддитивно, не затирает пользовательские продукты.
- WaterLogEntry валидируется по порции и суточному пределу; JSON v3 включает
  воду/цели/оформление/напоминания и сохраняет совместимость v1/v2.
- Notification icon явно сохраняется при resource shrinking через raw/keep.xml.
- 44 теста проходят; строгий analyzer без замечаний. OSV проверил 118 точных
  Pub-версий: 0 известных advisory-совпадений на 31 октября 2026.
- Это расширение исходной частичной проверки, не завершение формального аудита.
  Runtime Android/Health Connect consent/реальная доставка уведомлений требуют
  проверки на устройстве. Подробности сборки: [build_verification.md](build_verification.md).

## Дополнение quant 1.3.0

Локализация и онбординг не отправляют данные в сеть. Разрешения Health Connect
и уведомлений запрашиваются только кнопкой подключения. Исправлена гонка
первичной проверки доступа и явного запроса. JSON v4 включает выбранный язык,
старые версии мигрируют на системный язык. Импорт на онбординге также требует
подтверждения замены данных.

Сброс требует отдельного подтверждения, выбор категорий по умолчанию пустой.
Полный сброс предлагает экспорт, отменяет уведомления и очищает SharedPreferences.
Очистка всех коллекций и повторный посев атомарны внутри Isar. Между Isar и
SharedPreferences общей транзакции нет, это отражено в README.
