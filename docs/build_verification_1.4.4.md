# quant 1.4.4 — отчёт PNG, избранное и рецепты

## Реализация

Новых Flutter/Maven-зависимостей не добавлено. Сохранены Flutter/Riverpod/Isar,
локализация AppStrings, темы, обводки и существующий механизм добавления еды.

### Отчёт

- `lib/features/reports/report_data.dart` агрегирует данные по локальным дням.
  Отсутствующие дни исключены, явный ноль остаётся нулём. Средние содержат
  количество использованных дней, вода подписана как записанный объём.
- `report_screen.dart` содержит выбор 7/30 дней, загрузку, ошибки, предпросмотр
  и PNG из RepaintBoundary. Высота определяется содержимым; масштаб экспорта 2×.
- Вес и шаги читаются из Health Connect только после явного открытия отчёта.
  Новые разрешения автоматически не запрашиваются. Недоступность/ошибки отмечены
  в отчёте. Одно взвешивание показывается без изменения, отсутствие — явно.
- История целей не хранится: отчёт прямо указывает сравнение с текущей водой
  и шагами. Это сводка данных без диагнозов или рекомендаций.
- Android `ReportImages.kt` сохраняет PNG через MediaStore с IS_PENDING на
  Android 10+, удаляет незавершённую запись при ошибке. Android 8/9 запрашивает
  WRITE_EXTERNAL_STORAGE только по нажатию сохранения; разрешение ограничено
  maxSdkVersion=28. FileProvider выдаёт временный доступ только к cache/reports,
  ACTION_SEND передаёт content URI, не путь и не медицинские данные в Intent extras.
  Старые файлы для отправки удаляются при следующей отправке через сутки.
- Экран доступен внутри существующего AppLockGate. Экспорт по действию
  пользователя намеренно создаёт доступный другим приложениям файл; PNG не
  зашифрован. Защита входа не шифрует уже сохранённую копию в галерее.

### Избранное, частые продукты и рецепты

- `FoodProduct` дополнен stableKey, isFavorite, recipeJson; `FoodLogEntry` —
  productKey. Схемы Isar сгенерированы. Идентификаторы существующих коллекций и
  пути БД сохранены. При открытии добавляются идентификаторы, старые записи
  дневника не переписываются. Поля добавлены без удаления старых данных.
- Ключи: catalogue:<id> для встроенного справочника, off:<barcode> для Open Food
  Facts, local:<time>:<secure-random> для собственных продуктов/рецептов. Поиск
  ключа и запись звезды выполняются в одной транзакции, повторный онлайн-продукт
  с тем же штрихкодом не создаёт новую строку.
- Рейтинг вычисляется из текущего дневника: сумма 1/(1 + возраст_в_днях/14).
  Запросы/открытия ничего не записывают. Удаление/изменение дневника вызывает
  обновление. Для старых записей без ключа допустимо только однозначное совпадение
  названия; при неоднозначности продукт не угадывается.
- `Recipe` хранит снимки ингредиентов и nullable КБЖУ, массу выхода и порции.
  Итоги считаются без промежуточного округления. Общие суммы масштабируются
  отдельно на готовый вес и число порций. Неизвестные показатели дают неполный
  расчёт; UI не показывает их как известный ноль и блокирует внесение порции.
- Рецепт — продукт с составом: выбор использует существующее окно массы и
  addProductToDiary. В дневнике остаётся снимок массы/названия/КБЖУ. Звезда
  сохраняется независимо от редактирования рецепта.
- `RecipesScreen`: список, создание, редактирование, удаление с подтверждением,
  ингредиенты из локального каталога, изменение массы, итоговый вес, дробные
  порции и предпросмотр трёх расчётов. В поиске еды доступны частые/звёзды/рецепты.
- BackupDocument v6 сохраняет новые поля и проверяет структуру/границы/повторы
  ключей при импорте. Старые v1–v5 читаются. Сброс продуктов также сбрасывает
  рецепты и избранное с повторным посевом каталога, не изменяя дневник.

## Проверки

- Build runner: новые поля в FoodProduct/FoodLogEntry, без заглушек.
- Unit/widget: формулы и дробные порции, изменение выхода, неизвестные значения,
  нечисловые/нулевые/отрицательные массы; оба периода отчёта, пропуски/нулевые
  значения, PNG при ширине 320 px и масштабе текста 1,6.
- Реальная Isar: избранное после закрытия/открытия, повторный штрихкод, частые
  продукты после добавления/удаления, снимок порции после правки/удаления рецепта,
  восстановление v6 и выборочный сброс с сохранением дневника.
- Health Connect mock: агрегированные шаги, ноль с записью, отсутствие записи.
- Android integration расширен сохранением фактического PNG через MediaStore
  и открытием системного share sheet через FileProvider. Эти проверки выполняются
  в [Actions](https://github.com/etowhite/quant-fitness-dashboard/actions/workflows/release_apk.yml).

## Ограничения

Полнота истории Health Connect зависит от разрешений и источников. Дни без
данных не восстанавливаются предположениями. Цели исторически не сохраняются.
Масса выхода проверяется также на допустимость КБЖУ на 100 г (до 1000 ккал,
до 100 г каждого макроэлемента), как и остальной справочник.

Локальный Android-эмулятор не запускается из-за DLL 0xC0000135. Отрисовка PNG и
проверки Isar локально не заменяют тест реальной галереи/получателя изображения
на телефоне. Android 8/9 legacy MediaStore требует отдельной проверки на таком
устройстве; CI использует Android 15. Доставка изображения выбранному адресату
через другое приложение находится вне quant; успех отправки означает открытие
системного меню, а не подтверждённую доставку.
